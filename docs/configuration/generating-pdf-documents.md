# Generating PDF documents

## Configuration

PDF documents are generated by default once the plugin is registered.
The `enabled` option can be used as a toggle, for instance with an environment variable:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          enabled: !ENV [MKDOCS_EXPORTER_PDF, true]
```

Each page gets a PDF document next to its HTML file (e.g. `guide/intro/index.pdf` for `guide/intro/index.html`).

### Choosing pages

By default, every page gets a PDF document. A page can opt out with its [front matter](../reference/front-matter.md):

```yaml
---
exporter:
  pdf:
    enabled: false
---
```

In explicit mode, pages have to opt in instead:

=== "`mkdocs.yml`"

    ```yaml
    plugins:
      - exporter:
          formats:
            pdf:
              explicit: true
    ```

=== "A page"

    ```yaml
    ---
    exporter:
      pdf:
        enabled: true
    ---
    ```

### While serving

To keep `mkdocs serve` responsive, documents are not generated while serving. Enable the `serve` option to generate them anyway:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          serve: true
```

The browser is then kept open from one rebuild to the next.

### Concurrency

Documents are rendered concurrently: by default, twice as many at a time as there are CPUs, up to 8 (rendering mostly waits for the browser, which then uses about 1.4 GB of memory). The number can be set, e.g. to use less memory:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          concurrency: 4
```

### Cache

Documents are kept in `.cache/plugin/exporter` (next to your configuration file) and reused by the next builds as long as their page, the plugin's options and the files they load from your website (stylesheets, scripts, images...) are unchanged.
Files loaded from other websites (e.g. a script from a CDN) are assumed not to change: delete the directory to start afresh.

Documents that may be incomplete (a file failed to load, a hook failed) are not kept, and the cache only keeps the documents of the last build.
The cache can be moved, or disabled:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          cache:
            enabled: false
            directory: .cache/plugin/exporter
```

### Links

Links to other pages of your website are resolved to absolute URLs, based on `site_url`.
Use the `url` option to point them somewhere else (e.g. where your website is published, when `site_url` is not set):

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          url: https://docs.example.com/
```

When there is no URL at all, links are relative to the PDF document, which works when documents are published alongside the website.
Links to anchors of the same page, and links to other websites, are left untouched.

### Document information

Documents are given the page's title, an author, a subject and keywords, shown by PDF readers and used by search engines:

| Information | Taken from |
|---|---|
| Title | The page's title |
| Author | The page's `author` metadata, or `site_author` |
| Subject | The page's `description` metadata, or `site_description` |
| Keywords | The page's `keywords` or `tags` metadata |

```yaml
---
author: Jane Doe
description: How to configure the plugin.
tags:
  - configuration
---
```

### Table of contents

Documents can start with a table of contents of the page's headings, with their page numbers, inserted after the front cover:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          toc:
            enabled: true
            title: Contents
            depth: 3 # Second and third-level headings
```

Pages without headings besides their title don't get one, nor do [books](books.md#table-of-contents), which have a table of contents of their own.
A page can do without one, or have one while the option is disabled, in its front matter:

```yaml
---
exporter:
  pdf:
    toc:
      enabled: false
---
```

Like the table of contents of books, its appearance can be changed with CSS or a template of your own (`toc.template`).
The page numbers are filled from a first print of the document, which is then printed again.

## Cover pages

Cover pages are added at the beginning (`front`) and at the end (`back`) of documents. They are [Jinja](https://jinja.palletsprojects.com/) templates rendering HTML, with styles of their own:

{{ previews("field-guide:5", "field-guide:6") }}

=== "`mkdocs.yml`"

    ```yaml
    plugins:
      - exporter:
          formats:
            pdf:
              covers:
                front: covers/front.html.j2
                back: covers/back.html.j2
    ```

These covers are those of the [Field Guide](../examples/index.md#the-field-guide) example, and the [Cover pages](../examples/cover-pages.md) example shows another one.

Templates have access to:

| Variable | Value | For instance |
|---|---|---|
| `page` | The page | {% raw %}`{{ page.title }}`, `{{ page.url }}`, `{{ page.parent.title }}` (its section), `{{ page.is_homepage }}`, `page.toc` (its headings){% endraw %} |
| `page.meta` | The page's metadata (front matter) | {% raw %}`{{ page.meta.description }}`{% endraw %} |
| `config` | The MkDocs configuration | {% raw %}`{{ config.site_name }}`, `{{ config.site_author }}`{% endraw %} |
| `extra` | The `extra` section of the configuration | {% raw %}`{{ extra.version }}`{% endraw %} |

The page's metadata are also available as variables (e.g. {% raw %}`{{ description }}`{% endraw %}).
When the [macros](https://github.com/fralau/mkdocs_macros_plugin) plugin is enabled, templates are rendered with its environment: its variables (such as `navigation`, every page of the website), macros and filters are available too.

- `<style data-mkdocs-exporter-teleport="head">` moves styles to the document's head: `@page :first` rules style the page of the front cover (e.g. without margins, with a background), and named pages the page of the back cover.
- Paths starting with `/` (like `/assets/images/logo.png`) are resolved from the root of the website.
- Headers and footers are not printed on cover pages, except on named pages of your own (set `content: none` on their margin boxes there).
- Decorations drawn in the background of the cover's page stay in place, whatever the space the theme leaves above the content: prefer them to elements as tall as the page, which may overflow onto a blank page.

### Per-page cover pages

Pages can override cover pages in their front matter (paths are relative to `mkdocs.yml`):

```yaml
---
exporter:
  pdf:
    covers:
      front: resources/templates/covers/special.html.j2
---
```

### Hiding cover pages

Pages can also opt out of cover pages:

```yaml
---
exporter:
  pdf:
    covers:
      enabled: false
---
```
