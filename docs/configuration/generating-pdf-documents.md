# Generating PDF documents

## Configuration

PDF documents are generated by default once the plugin is registered.
The `enabled` option can be used as a toggle, for instance with an environment variable:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          enabled: !ENV [MKDOCS_EXPORTER_PDF, true]
```

Each page gets a PDF document next to its HTML file (e.g. `guide/intro/index.pdf` for `guide/intro/index.html`).

### Choosing pages

By default, every page gets a PDF document. A page can opt out with its front matter:

```yaml
---
pdf: false
---
```

In explicit mode, pages have to opt in instead:

=== "`mkdocs.yml`"

    ```yaml
    plugins:
      - exporter:
          formats:
            pdf:
              explicit: true
    ```

=== "A page"

    ```yaml
    ---
    pdf: true
    ---
    ```

### While serving

To keep `mkdocs serve` responsive, documents are not generated while serving. Enable the `serve` option to generate them anyway:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          serve: true
```

### Concurrency

Documents are rendered concurrently, 4 at a time by default:

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          concurrency: 8
```

### Links

Links to other pages of your website are resolved to absolute URLs, based on `site_url`.
Use the `url` option to point them somewhere else (e.g. where your website is published, when `site_url` is not set):

```yaml
plugins:
  - exporter:
      formats:
        pdf:
          url: https://docs.example.com/
```

When there is no URL at all, links are relative to the PDF document, which works when documents are published alongside the website.
Links to anchors of the same page, and links to other websites, are left untouched.

### Document information

Documents are given the page's title, an author, a subject and keywords, shown by PDF readers and used by search engines:

| Information | Taken from |
|---|---|
| Title | The page's title |
| Author | The page's `author` metadata, or `site_author` |
| Subject | The page's `description` metadata, or `site_description` |
| Keywords | The page's `keywords` or `tags` metadata |

```yaml
---
author: Jane Doe
description: How to configure the plugin.
tags:
  - configuration
---
```

## Cover pages

Cover pages are added at the beginning (`front`) and at the end (`back`) of documents. They are [Jinja](https://jinja.palletsprojects.com/) templates rendering HTML:

=== "`mkdocs.yml`"

    ```yaml
    plugins:
      - exporter:
          formats:
            pdf:
              stylesheets:
                - resources/stylesheets/pdf.css
              covers:
                front: resources/templates/covers/front.html.j2
                back: resources/templates/covers/back.html.j2
    ```

    > :material-file-code: View the full content of this file [here](https://github.com/adrienbrignon/mkdocs-exporter/blob/master/mkdocs.yml).

=== "`resources/templates/covers/front.html.j2`"

    ```html
    <div class="front-cover">
      <img src="/assets/images/background.png">
      <section>
        <div class="brand">{% raw %}{{ config.site_name }}{% endraw %}</div>
        <div class="title">{% raw %}{{ page.title }}{% endraw %}</div>
      </section>
    </div>
    ```

    > :material-file-code: View the full content of this file [here](https://github.com/adrienbrignon/mkdocs-exporter/blob/master/resources/templates/covers/front.html.j2).

=== "`resources/templates/covers/back.html.j2`"

    ```html
    <div class="back-cover">
      <section>
        <div class="title">{% raw %}{{ config.site_name }}{% endraw %}</div>
      </section>
    </div>
    ```

    > :material-file-code: View the full content of this file [here](https://github.com/adrienbrignon/mkdocs-exporter/blob/master/resources/templates/covers/back.html.j2).

Templates have access to:

- `page`: the page (e.g. `{% raw %}{{ page.title }}{% endraw %}`, `{% raw %}{{ page.url }}{% endraw %}`);
- `config`: the MkDocs configuration (e.g. `{% raw %}{{ config.site_name }}{% endraw %}`);
- `extra`: the `extra` section of the configuration;
- the page's metadata (front matter), as variables.

When the [macros](https://github.com/fralau/mkdocs_macros_plugin) plugin is enabled, templates are rendered with its environment: its variables, macros and filters are available too.

Paths starting with `/` (like `/assets/images/background.png`) are resolved from the root of the website.
Styles can be moved to the document's head with `<style data-teleport="head">`, to style pages with `@page` rules for instance.

If you use the template front cover page, do not forget to copy the [background image](https://raw.githubusercontent.com/adrienbrignon/mkdocs-exporter/master/docs/assets/images/background.png) to `docs/assets/images/background.png` in your project.

### Per-page cover pages

Pages can override cover pages in their front matter (paths are relative to `mkdocs.yml`):

```yaml
---
covers:
  front: resources/templates/covers/special.html.j2
---
```

### Hiding cover pages

Pages can also opt out of cover pages:

```yaml
---
hide:
  - covers
---
```
