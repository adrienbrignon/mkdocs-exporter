# Troubleshooting

## A page fails to render

When a page can't be rendered, the build fails once every other page has been rendered, with the reason for each failing page:

```
ERROR   -  [mkdocs-exporter.pdf] Failed to render pages:
- guide/intro.md: Timed out after 60000 ms waiting for the page to be ready
  JavaScript errors:
    - ...
  Failed requests:
    - http://127.0.0.1:41234/docs/assets/missing.png (HTTP 404)
```

- **Rendering failed**: a script prevented the page from being prepared; the error tells which one.
- **Timed out**: the page didn't finish rendering in time (`formats.pdf.browser.timeout`, 60 seconds by default), typically because a [hook](../configuration/customizing-documents.md#scripts) never returns or a resource takes too long to load.

## Something is missing from documents

- **Images or styles**: failed requests to your website are logged as warnings. Paths starting with `/` are resolved from the root of the website, and then from `site_url`'s path.
- **Content drawn by scripts** (diagrams, charts...): scripts may need more time, use a [hook](../configuration/customizing-documents.md#scripts) or `formats.pdf.browser.delay`.
- **Collapsed or hidden content**: `<details>` blocks are opened, but content hidden by your theme's print styles stays hidden; override them in a [stylesheet](../configuration/customizing-documents.md#stylesheets).
- **Content cut off on the right**: content wider than the page (large tables, long lines of code...) is cut off, instead of shrinking every page of the document; make it fit in a [stylesheet](../configuration/customizing-documents.md#stylesheets), e.g. `pre code { white-space: pre-wrap; }`.

## Getting more details

Enable the debug logs of the plugin, and the browser's console:

```yaml
plugins:
  - exporter:
      logging:
        level: debug
      formats:
        pdf:
          browser:
            debug: true
```

JavaScript errors raised by your website's own scripts are logged at the debug level: they usually happen on the website too and don't affect documents.

## Generating documents faster

- Documents are not generated by `mkdocs serve` by default; disable them for regular builds too with an environment variable (`enabled: !ENV [MKDOCS_EXPORTER_PDF, true]`).
- Keep the [cache](../configuration/generating-pdf-documents.md#cache) between builds (on CI too): only the pages that changed are rendered again.
- Raise `formats.pdf.concurrency` on machines with more cores.
- Combining pages renders them a second time: disable the aggregator when you don't need it.
- If you added [Paged.js](../configuration/customizing-documents.md#using-paged-js), keep in mind that it lays out pages much more slowly than the browser.
